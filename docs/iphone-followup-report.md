# Исправления интро, размеров и обратных переходов — 19.11.2026

Работа по ТЗ «LOFT Store — исправление интро, размеров и анимаций». Изменения ограничены клиентским интерфейсом и сеткой брюк/джинсов в админке. Тексты Telegram-уведомлений и процессы оплаты не изменялись.

1. **Изменённые файлы.** Полный перечень клиентского репозитория приведён ниже. В админке: `src/pages/ProductsPage.tsx`, `src/pages/CategoriesPage.tsx`, новый `src/lib/shopSizeGrid.ts`, RU/UZ-словари, `tests/shop-grid.test.ts`, три основных документа. Графы Graphify обновлены по AST в обоих репозиториях; это не семантическая индексация вложений.

2. **Дизайн интро.** Бренд LOFT Store строго по центру, единая позиция между выбором языка и тремя этапами. Системная гарнитура, navy/cream/gold, существующие скругления и иконки. Высота сцены фиксирована, общие элементы не скачут. Основные кнопки одной геометрии; «Пропустить» есть только на первых ознакомительных этапах.

3. **Анимация интро.** Framer Motion использует общие motionTiming.page=340 ms и motionEase, направленный push ±100%. Назад меняет направление; реф и disabled блокируют конкурирующие нажатия до завершения текущей анимации. Индикатор движется той же кривой. Reduced motion — мгновенная смена. Жестов переключения в прежнем интро не было, новые не добавлялись.

4. **Задержка первого экрана.** Прежний компонент показывал загрузочное состояние, пока не пришли private preferences. Теперь обязательный выбор языка рендерится сразу после готовности React, независимо от профиля/каталога/изображений; интро включено в основной бандл. Система шрифтов не ждёт webfont. Независимые загрузки могут идти параллельно. Подсказка localStorage хранит только язык и факт завершения по аккаунту; запись — после проверенного серверного ответа, серверное состояние имеет приоритет. Она не даёт доступа к приватным данным. В тесте запросы профиля и каталога удерживаются, но язык уже доступен. Нулевая задержка сети/загрузки JS или Telegram SDK не обещается.

5. **Удалённые элементы размеров.** Удалены SavedSizes и SavedSizeRow, пункт профиля, ветка маршрута и оставшийся редактор размеров в CustomerPreferences. Старое ?section=sizes заменяется профилем без пустой страницы. Профиль не содержит ссылки на удалённый раздел.

6. **Совместимость размеров.** Private-модель, RPC, сохранённые размеры, справочник, таблицы и подсказки ProductPage сохранены. Сохранение контактов не меняет размеры. Проверены legacy-значения, явные соответствия и приблизительные подсказки; размер покупки автоматически не выбирается.

7. **Брюки и джинсы.** Сетка магазина: 36,38,40,42,44,46,48,50,52,54,56. Клиент показывает её в прежней панели, сортировка числовая. Значения, у которых нет реального варианта, недоступны для покупки/подписки; существующий отсутствующий вариант может сохранять прежнюю подписку на поступление. Админка создаёт новые товары по этой сетке, редактор существующего товара сохраняет реальные legacy-значения по цвету и остатки. При копировании restricted-товара новые остатки вводятся явно, оригинал не меняется. Редактор соответствующих подкатегорий сохраняет numeric и 11 значений. Система производителя уточняется отдельно через существующие размерные таблицы, сетка не является конвертацией M→число.

   Применена миграция `20261119170446_pants_jeans_shop_grid.sql` только для defaults подкатегорий. Производственная проверка до/после: 15 вариантов, общий остаток 141, одинаковый fingerprint всех полей этих вариантов. Три затронутых товара: Jacob & Cohen jeans (50 ед.), Loro Piana jeans (50 ед.), Zegna Spring-Summer (41 ед.). У всех текущие значения 48–56; буквенных вариантов в них не найдено, ручное сопоставление сейчас не требуется. В случае появления старых буквенных вариантов UI сохраняет их и предупреждает о ручном сопоставлении. Исторические заказы SQL не обновляет.

8. **Настройки.** Удалены пункт «Как пользоваться приложением» и событие повторного запуска интро. Обычный выбор языка и остальные настройки сохранены. Серверное завершение обучения остаётся идемпотентным; противоречащий локальной подсказке сервер возвращает обязательный выбор языка.

9. **Кнопка спецзаказа.** Корзина и форма заявки используют один PrimaryActionButton: min-height 48 px, rounded-xl, одинаковая палитра/иконографика/отступы. Существующий useFloatingAction сохраняет измерение navbar, safe area, нижний запас содержимого и скрытие при открытой мобильной клавиатуре. Реф для самолётика, валидация, upload, idempotency и серверная отправка сохранены. Браузерная проверка сравнивает фактические height/radius обеих кнопок, проверяет расстояние до navbar и focus/blur.

10. **Подтверждённые причины сбоев возврата.**
    - Выходящий Bottom Sheet остаётся в DOM на 200 ms. Telegram Back выбирал его data-loft-dismiss повторно, хотя размер уже выбран. Исходный регрессионный тест без ожидания exit воспроизводил это: route не менялся и обратный переход не начинался.
    - Native View Transition привязан к размеру viewport-снимка. Изолированный браузерный тест с анимацией 1000 ms и изменением viewport после ready завершился в Chrome за 22 ms, WebKit за 157 ms; контроль без resize — 1018/1121 ms. Повторить: `node scripts/probe-native-viewport.mjs`. Это воспроизводимая уязвимость механизма, согласующаяся с [CSS View Transitions specification](https://drafts.csswg.org/css-view-transitions-1/). Resolve finished не гарантирует полную длительность. Это НЕ запись конкретного физического iPhone и не доказательство причины каждого его кадра. Сохранённый размер сам по себе не объявляется причиной без доказательств.

11. **Общий механизм возврата.** Прямое открытие сохраняет фирменный native shared transition. Обратное движение фото делает один fixed WAAPI-слой с прежними easing/340 ms, без viewport snapshot. Существующий origin восстанавливает список, прокрутку, placement и фильтры перед измерением. На resize/visualViewport resize/scroll оставшаяся часть движения перенаправляется из текущего положения, не перезапускается с исходной точки. Смена цвета мягко согласуется с фото исходной карточки. Chrome неподвижен; exit-панели помечены через useIsPresent/closing marker, исключены из Back и следующего кадра. При отсутствии источника или цели — короткое растворение; rapid interruption очищает слой/visibility/listeners. Искусственных пауз для маскировки нет; остаётся прежнее ограниченное ожидание реального DOM/decode. Scroll anchoring отключён только на время product transition.

12. **Проверки.** Production-сборки обоих репозиториев успешны. Node: клиент 89/89, админка 21/21. Полный локальный SQL-прогон прошёл, в том числе fingerprint products/variants/orders с legacy M и остатком 7 после миграции. Браузерные прогоны Chromium mobile/desktop и WebKit: 177 проверок основных потоков + 81 проверка возвратов/спецзаказов/refunds/abandoned checkout; финальный повторный прогон новых 13 сценариев и общего return audit — 78/78 (включая 39 проверок нового набора). Проверены все источники товаров (главная, бренд, категории, подкатегории, поиск, избранное, новые/популярные/скидки), рекомендации, цвета, галерея, таблица, подписка отсутствующего варианта, быстрый size→Back, resize на возврате и повторное открытие. RU/UZ, dark/light, reduced motion, первый/повторный запуск и серверная коррекция hint покрыты. Заказы/оплата/контакты/очереди уведомлений проверены локально через существующие SQL/Node/browser fixtures, без рассылки реальным клиентам. Общий lint остаётся красным из-за прежних ошибок: клиент 414 errors/12 warnings против исходных 418/12; админка 258/15 без изменения. Новых диагностик по file/rule не добавлено. Снимки light RU/dark UZ интро и кнопки спецзаказа визуально просмотрены. Дополнительно production-бандлы проверены под точными CSP из vercel.json: товар, админский сеанс MFA, главная и редактор товара прошли без CSP-нарушений. Для этой проверки сборки использовали fixture-ключ; реальный Realtime/доставка уведомлений этим smoke-тестом не подтверждаются.

13. **Проверка на реальном iPhone остаётся обязательной.** Физический Telegram iOS здесь недоступен. Нужно на устройстве проверить: холодный запуск и выбор языка; быстрый размер→Назад; изменение высоты Telegram при клавиатуре/сворачивании; возврат из всех списков после цвета, галереи и таблицы; сохранность острова/navbar и позиции прокрутки; кнопку спецзаказа при комментарии/upload и safe area. Эмуляция WebKit и успешная сборка не заменяют эту приёмку. Исправлены воспроизведённые классы ошибок; абсолютное отсутствие рывков на устройстве до этой проверки не утверждается.
