# LOFT Store — автоматическое локальное время

Актуализация основного ТЗ от 16 ноября 2026. Этот раздел заменяет прежние требования о ручном вводе/выборе часового пояса.

1. Клиентское приложение и админка автоматически получают часовой пояс устройства через `Intl.DateTimeFormat().resolvedOptions().timeZone`. Не используются GPS, координаты, разрешения геолокации, IP и сторонние сервисы определения местоположения. Выбор часового пояса в интерфейсе отсутствует.
2. Абсолютные даты заказов, спецзаказов, истории, возвратов, уведомлений, рассылок, создания/изменения записей и запланированных событий показываются в локальном времени устройства. Оба приложения используют единый механизм с RU/UZ. Кэш хранит timestamps, а не отформатированные даты другой зоны; изменение зоны/языка обновляет представление.
3. Настройки напоминаний содержат только начало/конец рабочего дня, сроки правил, интервал повторения и переключатели. Серверные рабочие часы всегда используют `Asia/Tashkent`, независимо от страны менеджера; в интерфейсе показывается локальная проекция графика на текущую дату с подписью «По вашему местному времени» / «Sizning mahalliy vaqtingiz bo‘yicha». При явном сохранении ввод конвертируется обратно в Asia/Tashkent; открытие страницы и сезонная смена смещения не меняют фактический график. Исходные часы Узбекистана доступны второстепенной подписью.
4. При новом планировании менеджер выбирает местную дату/время. Подпись: «По вашему местному времени» / «Sizning mahalliy vaqtingiz bo‘yicha». Выбор преобразуется в ISO UTC с `Z` до передачи серверу. После выбора/сохранения смена зоны меняет только отображение, а не момент отправки. Несуществующее местное время во время весеннего перехода DST отклоняется; повторный осенний час разрешается браузером в первое вхождение.
5. Все существующие абсолютные timestamps и уже запланированные кампании сохраняются без пересчёта. Настройка часового пояса PostgreSQL, Cron, очереди и финансовые записи не меняются. Рабочие часы магазина отделены от отображения дат пользователю.
6. Проверить RU/UZ, Ташкент/Ригу/Нью-Йорк, переход через границу суток, зимнее/летнее время, неизменность сохранённой кампании после смены зоны, работу напоминаний для менеджера за рубежом. Проверки используют изолированные данные; реальные сообщения и кампании для тестов не запускаются.
