# LOFT Store — исправления карточек товаров, размеров, анимаций и интерфейса

## 1. Общая задача

Необходимо выполнить очередной этап доработок LOFT Store по результатам тестирования клиентского Telegram Mini App на iPhone и административной панели.

Репозитории:

- `ttta999/loft-store` — клиентское приложение, API, серверная логика и Supabase.
- `ttta999/loft-store-admin` — административная панель.

Перед внесением изменений изучи актуальный код обоих репозиториев, существующие компоненты интерфейса, маршрутизацию, анимации карточек товаров, модель размеров, таблицы размеров и систему кеширования.

Необходимо исправить описанные ниже недочёты, сохранив существующий дизайн и работающую бизнес-логику.

**Общие требования:**

- Сохранить фирменный стиль LOFT Store.
- Поддерживать светлую и тёмную темы.
- Поддерживать русский и узбекский языки.
- Использовать существующие компоненты и анимации.
- Не создавать параллельные системы кеширования и навигации.
- Не проводить глобальный рефакторинг.
- Не нарушать заказы, спецзаказы, оплату, возвраты и Telegram-уведомления.
- Все изменения Supabase выполнять через новые миграции при необходимости.
- Не изменять уже применённые миграции.

## 2. Исправить заголовок страницы «Спецзаказ»

### Текущая проблема

На странице создания спецзаказа отображается заголовок:

**Спецзаказ**

Под ним расположен текст:

«Привезём товар по вашему описанию или ссылке».

При этом справа отсутствует соответствующая иконка раздела.

### Требуемое изменение

Привести верхний информационный блок страницы к общему стандарту LOFT Store.

Сделать:

- Слева — заголовок «Спецзаказ».
- Справа — фирменная иконка спецзаказа.
- Удалить текст «Привезём товар по вашему описанию или ссылке».

Использовать ту же иконку глобуса, которая используется для спецзаказов в нижней навигации и профиле.

### Дизайн

Сохранить существующую карточку:

- Скруглённые углы.
- Фирменный фон.
- Существующую границу.
- Тёмно-синий текст в светлой теме.
- Белый текст в тёмной теме.

Иконка справа должна быть выровнена по центру относительно заголовка.

Не добавлять новую отдельную плашку для иконки, если существующий компонент заголовка предусматривает простую иконку справа.

После удаления описания уменьшить высоту карточки до нормальной высоты заголовка с сохранением комфортных отступов.

Не изменять поля заявки, загрузку фотографии, отправку спецзаказа и серверную логику.

## 3. Унифицировать заголовки новых страниц профиля

### Текущая проблема

На новых страницах профиля верхние информационные карточки оформлены неодинаково.

На части страниц уже используется удачный стандарт:

- Название раздела слева.
- Небольшое описание под названием при необходимости.
- Соответствующая иконка справа.

Однако на страницах «Мои размеры», «Уведомления о поступлении» и «Личные данные» этот стандарт соблюдён не полностью.

### Задача

Использовать единый компонент заголовка для всех перечисленных страниц.

Сохранить фирменный вид информационных карточек, как в разделе «Избранное».

### 3.1. Страница «Мои размеры»

Заголовок:

**Мои размеры**

Описание:

«Сохраните размеры для удобного выбора товаров».

Справа — иконка линейки.

Сохранить функциональность выбора и редактирования размеров.

Не дублировать заголовок ниже информационной карточки.

### 3.2. Страница «Уведомления о поступлении»

Заголовок:

**Уведомления о поступлении**

Описание:

«Товары, поступления которых вы ожидаете».

Справа — иконка колокольчика.

Использовать существующую круглую или обычную фирменную иконку заголовка, согласованную с другими страницами.

Не использовать иконку коробки вместо колокольчика.

### 3.3. Страница «Личные данные»

Заголовок:

**Личные данные**

Описание:

«Ваши контакты и адреса доставки».

Справа — иконка пользователя.

Сохранить существующие формы:

- Имя.
- Телефон.
- Предпочитаемый способ получения.
- Сохранённые адреса.
- Кнопку сохранения.

### 3.4. Общие требования

Все три карточки должны иметь:

- Одинаковую систему внутренних отступов.
- Одинаковые размеры заголовков.
- Одинаковые стили описания.
- Одинаковое расположение иконок.
- Согласованную минимальную высоту.
- Корректную адаптацию для длинных заголовков.

Не использовать вручную разные CSS-стили для одинаковых элементов, если можно переиспользовать общий компонент.

Проверить адаптивность и обе темы.

## 4. Добавить полноценный пустой экран уведомлений о поступлении

### Текущая проблема

Если у клиента нет подписок на поступление товаров, отображается только обычная строка:

«Активных подписок пока нет».

Из-за этого страница выглядит незавершённой по сравнению с разделом «Избранное».

### Требуемый дизайн

Использовать тот же дизайн пустого состояния, что и в разделе «Избранное».

Структура:

1. Верхняя информационная карточка с заголовком и колокольчиком.
2. Ниже — отдельная большая карточка пустого состояния.
3. По центру карточки — круглая иконка колокольчика.
4. Под ней — короткий текст.

### Текст

**Пока нет уведомлений о поступлении**

«Выберите отсутствующий размер товара и нажмите „Уведомить о поступлении“, чтобы узнать, когда он снова появится».

Текст должен быть аккуратно выровнен по центру.

Не делать его чрезмерно длинным на мобильных устройствах.

### Дизайн

Использовать существующий компонент пустого избранного или общий компонент `EmptyState`, если он есть в проекте.

Сохранить:

- Фон карточки.
- Границы.
- Скругления.
- Размер круглой иконки.
- Внутренние отступы.
- Стили основного и второстепенного текста.

Не добавлять кнопку, которая никуда не ведёт.

Если есть смысл добавить кнопку «Перейти к товарам», использовать существующий маршрут каталога и фирменную анимацию перехода. Кнопка необязательна.

### Логика

Пустое состояние показывать только после успешной проверки того, что активных подписок действительно нет.

Во время загрузки показывать существующий skeleton или ранее закешированные данные.

Не показывать пустое состояние на мгновение перед завершением запроса.

Если произошла ошибка загрузки, показывать состояние ошибки с повторной попыткой, а не сообщение об отсутствии подписок.

Добавить русский и узбекский переводы.

## 5. Исправить обратную анимацию карточки товара из раздела брендов

### Текущая проблема

При переходе:

Главная → Бренды → Loro Piana → Карточка товара

Анимация открытия товара теперь работает правильно.

Однако при закрытии карточки товара обратная анимация дёргается.

Это наблюдается в реальном Telegram Mini App на iPhone.

### Требуемое поведение

При закрытии карточки товара должна воспроизводиться плавная обратная анимация, аналогичная анимации из категорий и других работающих разделов.

После закрытия пользователь должен вернуться:

- К тому же бренду.
- К той же позиции прокрутки.
- К исходной карточке товара.

### Что проверить

Изучить существующую систему:

- Анимации открытия карточки.
- Анимации закрытия карточки.
- Исходный DOM-элемент карточки.
- Идентификаторы размещения товара.
- Сохранение положения карточки.
- Сохранение изображения.
- Восстановление списка бренда.
- Работа React Router.
- Жизненный цикл компонентов при закрытии.

Особое внимание уделить ситуациям, когда при возврате:

- Исходная карточка ещё не восстановилась в DOM.
- Изменилось положение карточки из-за прокрутки.
- Изображение ещё не загружено.
- Родительская страница перерисовывается во время анимации.
- Одновременно запускаются две анимации.
- Изменяются размеры или координаты исходного элемента.

### Требования

Не менять анимацию открытия, если она уже работает правильно.

Исправить именно механизм обратного перехода.

При необходимости сохранять координаты и контекст исходной карточки перед открытием товара.

Обеспечить правильную синхронизацию восстановления страницы и запуска обратной анимации.

Не добавлять искусственные задержки, которые только маскируют проблему.

Использовать существующую систему product transitions.

## 6. Показывать «Таблицу размеров» только при наличии реальной таблицы

### Текущая проблема

В карточках товаров действие «Таблица размеров» отображается даже тогда, когда для товара, бренда или категории не создана подходящая таблица.

Клиент нажимает на него и видит пустое окно или бесконечную загрузку.

Это некорректно.

### Новое поведение

**Если подходящей активной таблицы размеров нет, действие «Таблица размеров» вообще не должно отображаться в карточке товара.**

Не нужно показывать неактивную кнопку или пустую плашку.

### 6.1. Правила определения таблицы

Использовать действующий приоритет:

1. Индивидуальная таблица товара.
2. Подходящая таблица бренда.
3. Таблица подкатегории.
4. Таблица категории.

Проверить точный порядок текущей реализации и сохранить предусмотренную бизнес-логикой специфичность.

Учитывать:

- Активность таблицы.
- Привязку к текущему товару.
- Категорию и подкатегорию.
- Бренд.
- Наличие фактических данных в таблице.

Пустую таблицу без строк и колонок не считать доступной.

### 6.2. Отображение кнопки

Если таблица существует и доступна — показывать компактную строку «Таблица размеров» под выбором размера.

Если таблицы нет — не показывать строку вообще.

При этом расстояние до кнопки «В корзину» должно автоматически адаптироваться.

Не оставлять пустое место от скрытого блока.

### 6.3. Исправить загрузку

Сейчас таблица размеров иногда отображает «Загрузка», после чего ничего не происходит.

Нужно установить причину:

- Повторный запрос.
- Ошибка RPC.
- Неправильная привязка.
- Проблема кеша.
- Ошибка состояния компонента.
- Необработанное исключение.
- Гонка запросов при переключении товаров.
- Ошибка авторизации или доступа к данным.

Не скрывать реальные ошибки за бесконечным спиннером.

### 6.4. Кеширование таблиц размеров

Подключить таблицы размеров к существующему механизму кеширования клиентского приложения.

Кешировать:

- Доступность подходящей таблицы.
- Идентификатор таблицы.
- Её содержимое.

Использовать ключи, которые учитывают товар и нужные параметры привязки.

Избегать ситуации, когда таблица предыдущего товара ошибочно показывается на следующем.

При повторном открытии того же товара использовать кеш.

При изменении таблиц в админке обеспечить корректную инвалидацию или фоновую перепроверку.

Нельзя кешировать отсутствие таблицы навсегда: менеджер может добавить её позже.

### 6.5. Поведение при ошибках

Не путать три состояния:

- Таблица существует.
- Таблицы нет.
- Не удалось проверить наличие таблицы.

При сетевой ошибке не фиксировать состояние «таблицы нет» как достоверное.

Предусмотреть ограниченное ожидание и понятную обработку ошибки.

Если проверка доступности выполняется в фоне, не допускать скачков интерфейса и резкой перестройки блока товара.

### 6.6. Тестирование

Проверить:

- Товар с индивидуальной таблицей.
- Товар с таблицей бренда.
- Товар с таблицей подкатегории.
- Товар с таблицей категории.
- Товар без таблицы.
- Скрытую таблицу.
- Пустую таблицу.
- Повторное открытие товара.
- Переключение между разными товарами.
- Добавление таблицы через админку после предыдущего отсутствия.
- Обновление существующей таблицы.

## 7. Исправить несовместимость сохранённых буквенных и цифровых размеров

### Текущая проблема

В профиле клиент может сохранить размер брюк M.

Однако некоторые товары в каталоге используют цифровые размеры.

В таком случае приложение не понимает, какой размер считать персональным и где показывать подсказку «Ваш размер».

### Цель

Сделать сохранённые размеры полезными при различных размерных системах.

При этом нельзя использовать универсальную конвертацию вроде:

M = 42

поскольку она не подходит всем брендам и категориям.

### 7.1. Не менять все товары на одну систему

Не переводить автоматически все товары каталога в буквенные или цифровые размеры.

Сохранить реальные обозначения размеров, указанные производителями.

Не менять существующие варианты товаров, остатки и оформленные заказы.

### 7.2. Добавить безопасные соответствия размеров

Использовать существующую модель размерных систем или расширить её, если необходимо.

Соответствие должно учитывать:

- Тип товара.
- Категорию и подкатегорию.
- Бренд, если его размеры отличаются.
- Исходную систему.
- Целевую систему.

Например, для определённой модели брюк может быть задано соответствие буквенных и цифровых размеров.

Но это соответствие нельзя автоматически применять ко всем брюкам магазина.

### 7.3. Источник соответствий

Приоритет:

1. Подтверждённая таблица размеров конкретного товара.
2. Подтверждённая таблица бренда для соответствующей категории.
3. Подтверждённая таблица категории, если она содержит явные соответствия.

Не выводить размер на основании догадки.

Не создавать несуществующие соответствия между M, EU 42, IT 44 и другими обозначениями.

Если данные производителя неоднозначны или соответствие не задано, не показывать ошибочную персональную подсказку.

### 7.4. Управление в админке

Использовать недавно реализованный визуальный редактор таблиц размеров.

Если таблица содержит колонки разных систем и подтверждённые соответствия, клиентское приложение может использовать эти данные для персональной подсказки.

Не требовать создания отдельного дублирующего справочника, если текущие таблицы размеров уже позволяют однозначно определить соответствие.

Если существующая структура таблиц не подходит для надёжной машинной интерпретации, создать явное структурированное поле соответствий или отдельную модель.

Не пытаться автоматически интерпретировать произвольные текстовые ячейки с неоднозначными значениями.

### 7.5. Поведение в карточке товара

Если клиент сохранил размер M, а товар использует цифровые размеры:

- Найти подтверждённое соответствие именно для этого товара или подходящей размерной системы.
- Если найдено однозначное соответствие — показать «Ваш размер» напротив цифрового варианта.
- Если соответствует диапазон размеров либо несколько вариантов — не выбирать один случайно.
- Если соответствия нет — не показывать персональную подсказку.

Клиент всегда выбирает фактический вариант товара самостоятельно.

### 7.6. Дополнительная рекомендация по UX

В профиле сохранить возможность указывать размеры в тех системах, которые реально используются соответствующей категорией.

Если у брюк есть несколько размерных систем, можно позволить клиенту отдельно сохранять размер для каждой системы.

Это полезнее и надёжнее, чем пытаться угадать соответствие по одному буквенно-цифровому значению.

Не перегружать профиль обязательными дополнительными полями.

### 7.7. Проверка

Протестировать:

- M → цифровой размер по подтверждённой таблице.
- EU → UK для обуви при наличии корректных соответствий.
- Размер без соответствия.
- Несколько возможных соответствий.
- Разные бренды с различными размерными сетками.
- Товар с индивидуальной таблицей.
- Товар без таблицы.

Не допускать неверных рекомендаций размера.

## 8. Исправить обратные анимации карточек товаров во всех разделах

### Текущая проблема

Помимо раздела брендов, обнаружена ещё одна ситуация:

Главная → Карточка товара → Выбор размера → Назад.

После выбора размера и закрытия карточки товара обратная анимация дёргается.

Аналогичная проблема потенциально может проявляться и в других разделах.

### Задача

Провести общий аудит анимаций открытия и закрытия карточек товаров.

Проверить все точки входа:

- Главная.
- Новые товары.
- Популярные товары.
- Категории.
- Подкатегории.
- Бренды.
- Поиск.
- Избранное.
- Рекомендованные товары.
- Дополнения к образу.
- Другие списки товаров.

### Особые сценарии

Проверить закрытие карточки после:

- Выбора размера.
- Изменения цвета.
- Просмотра фотографий.
- Прокрутки описания.
- Открытия и закрытия таблицы размеров.
- Добавления в корзину.
- Добавления в избранное.
- Подписки на поступление.
- Просмотра рекомендаций.
- Возврата из другого товара.

### Предполагаемые технические причины для проверки

- Изменение высоты карточки после выбора размера.
- Неправильный момент измерения координат.
- Повторное создание исходного элемента.
- Прокрутка страницы во время обратной анимации.
- Конфликт анимации маршрута и анимации фотографии.
- Изменение состояния товара во время закрытия.
- Повторная загрузка списка.
- Необработанный переход между товарами.
- Изменение положения нижней навигации.
- Конфликт с анимацией Bottom Sheet.

Это гипотезы для проверки, а не заранее установленная причина.

### Требования к исправлению

Сделать обратную анимацию столь же плавной, как открытие.

Обеспечить стабильное положение исходной карточки во время возврата.

Не сбрасывать прокрутку до завершения необходимой части перехода.

Не запускать одновременно конфликтующие анимации.

Не создавать отдельные исправления для каждого списка, если причина находится в общем механизме product transitions.

Не менять фирменную продолжительность, easing и стиль переходов без необходимости.

Если исходная карточка временно недоступна, использовать аккуратный fallback закрытия без рывков.

Учитывать `prefers-reduced-motion`.

### Обязательная проверка

Провести тестирование в мобильном Telegram WebView на iOS или максимально близкой среде.

Браузерные тесты не должны быть единственным подтверждением исправления.

Проверить плавность как при светлой, так и при тёмной теме.

# ЧАСТЬ II. АДМИНИСТРАТИВНАЯ ПАНЕЛЬ

## 9. Переделать кнопки «Добавить» в фирменном стиле LOFT

### Текущая проблема

В административной панели на страницах управления каталогом кнопки добавления выглядят неодинаково и недостаточно аккуратно.

Особенно это заметно в разделах:

- Бренды.
- Категории.
- Подкатегории.
- Товары.

Например, на странице брендов кнопка «Добавить» узкая, а текст переносится на две строки.

### Требуемый дизайн

Использовать единый фирменный компонент основной кнопки добавления.

Структура:

Иконка `+` слева.

Текст справа.

Примеры:

**+ Добавить бренд**

**+ Добавить категорию**

**+ Добавить подкатегорию**

**+ Добавить товар**

### Внешний вид

Использовать:

- Фирменный тёмно-синий фон в светлой теме.
- Фирменное оформление активной кнопки в тёмной теме.
- Белый или другой контрастный текст.
- Существующие скругления LOFT.
- Единые внутренние отступы.
- Единую высоту.
- Одинаковую толщину иконки.
- Плавный hover и active state.

На desktop текст не должен переноситься на две строки.

Не делать кнопку чрезмерно узкой.

Не использовать разные варианты оформления для одной и той же функции на разных страницах.

### Расположение

Размещать кнопку в логичном месте шапки страницы справа.

Не допускать конфликта с кнопкой «Обновить».

Если на маленьком экране обе кнопки не помещаются:

- Использовать адаптивный перенос действий.
- При необходимости сокращать второстепенные подписи.
- Сохранять видимость основной кнопки добавления.

Не уменьшать текст до нечитаемого размера.

### Разделы

#### Бренды

Кнопка:

«+ Добавить бренд».

#### Категории

Кнопка:

«+ Добавить категорию».

Для добавления подкатегории использовать тот же стиль с названием:

«+ Добавить подкатегорию».

#### Товары

Кнопка:

«+ Добавить товар».

### Функциональность

Не менять существующую логику создания брендов, категорий, подкатегорий и товаров.

Проверить, что все кнопки открывают правильные формы и сохраняют существующие проверки.

Сохранить русский и узбекский переводы.

Не добавлять кнопкам фиктивную функциональность.

# ЧАСТЬ IV. ТЕСТИРОВАНИЕ

## 13. Клиентское приложение

### Заголовки

- Спецзаказ — заголовок и иконка глобуса, без старого описания.
- Личные данные — заголовок, описание, иконка.
- Мои размеры — заголовок, описание, иконка.
- Уведомления о поступлении — заголовок, описание, иконка.

Все страницы должны соответствовать единому стилю.

### Пустое состояние

- Нет подписок — отображается полноценная пустая карточка.
- Есть подписки — отображается список.
- Данные загружаются — не появляется ложное пустое состояние.
- Ошибка — показывается корректная повторная попытка.

### Таблицы размеров

- Есть подходящая таблица — кнопка отображается.
- Нет таблицы — кнопка отсутствует.
- Таблица неактивна — кнопка отсутствует.
- Таблица пустая — кнопка отсутствует.
- Повторное открытие использует кеш.
- После изменения в админке таблица обновляется.
- Нет бесконечной загрузки.
- Нет подмены таблицы другим товаром.

### Размеры

- Буквенный размер клиента и цифровой размер товара.
- Подтверждённая конвертация.
- Отсутствующее соответствие.
- Неоднозначное соответствие.
- Разные бренды.
- Разные размерные системы.
- Подсказка не приводит к автоматическому выбору.

### Анимации

- Главная → товар → выбор размера → назад.
- Бренды → бренд → товар → назад.
- Категория → товар → назад.
- Поиск → товар → назад.
- Избранное → товар → назад.
- Рекомендации → товар → назад.
- Дополнения к образу → товар → назад.
- Изменение цвета → назад.
- Просмотр галереи → назад.
- Добавление в корзину → назад.

Проверить отсутствие рывков, скачков и конфликтов анимаций.
