# LOFT Store — действующая дизайн-система

Сверено 17.11.2026 с `src/index.css`, компонентами и анимационными helpers (`b9b9e99`). Это описание существующего интерфейса, а не предложение редизайна. [PRD](PRD.md), [архитектура](ARCHITECTURE.md), [система админки](https://github.com/ttta999/loft-store-admin/blob/main/docs/DESIGN_SYSTEM.md).

## Цвета и темы

Светлая палитра чаще задана inline Tailwind-значениями, тёмная — `@theme` в [index.css](../src/index.css). Не придумывать несуществующие `--surface-*` переменные.

| Роль | Светлая | Тёмная / токен |
|---|---|---|
| Фон | `#F5F1E8` | `#0b111e`, `--color-dark-bg`, `bg-dark-bg` |
| Карточка | `#FBF9F4` | `#151f33`, `--color-dark-card` |
| Активная/вложенная поверхность | `#F5F1E8` или `#E8E2D5` | `#22304a`, `--color-dark-accent` |
| Граница | `#E8E2D5` | `#31415f`, `--color-dark-border` |
| Основной текст | `#1B2A4A` | `#ffffff` |
| Второстепенный текст | `#8A8275` | `text-gray-300`; часть placeholder — `gray-500` |
| Золото | `#C9A961` | `--color-gold: #c9a961` |
| Основное действие | Navy фон, белый текст | Золотой фон, navy текст по компоненту |
| Скидка/часть ошибок | `#9B3B3B` | Красные оттенки существующего компонента |

Sonner использует `.loft-toaster` и реальные CSS variables:

| Состояние | Light: bg / text / border | Dark: bg / text / border |
|---|---|---|
| normal | `#fbf9f4 / #1b2a4a / #e8e2d5` | `#151f33 / #f3f4f6 / #31415f` |
| success | `#edf7ee / #22613a / #c3dfc9` | `#142e29 / #a7e3bd / #2f5c4c` |
| info | `#edf2fa / #294a78 / #ccd9ed` | `#172940 / #b9d7ff / #345574` |
| warning | `#fff6e5 / #815a18 / #ebd5a8` | `#342a19 / #ecd49a / #665331` |
| error | `#fff0f0 / #9b3b3b / #ecc5c5` | `#351f2a / #f4b8bf / #6b3949` |

Статусные badges используют локальные Tailwind `green/blue/purple/red/yellow` классы, а не обязательно toast variables. Брать состояние из соответствующего экрана; не перекрашивать финансовый статус ради эстетики. Тема `light/dark/system` хранится в Zustand; тёмные классы зависят от `.dark` на `<html>`. Общий переход цветов — 300 ms `ease`.

## Типографика и геометрия

Основной шрифт — системный стек `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, Oxygen, Ubuntu, Cantarell, 'Fira Sans', 'Droid Sans', 'Helvetica Neue', sans-serif`. Внешний брендовый font-файл не подключён.

| Применение | Используемый размер |
|---|---|
| Остров LOFT | `text-lg` (18 px), `font-bold`, `tracking-wide` |
| Заголовок карточки профиля | `text-xl` (20 px), `font-bold` |
| Основной текст / поля | `text-base` (16 px) |
| Строки товаров / формы | `text-sm` (14 px), medium/bold по роли |
| Подписи, описания карточек | `text-xs` (12 px), второстепенный цвет |

Это распространённые роли, не глобально навязанный единственный размер всех заголовков. Tailwind-шкала и конкретный компонент имеют приоритет. Поля ввода на мобильном сохранять `text-base`: меньший шрифт связан с нежелательным iOS focus-zoom.

Карточки обычно `rounded-2xl` (16 px), внутренние `rounded-xl` (12 px), остров и круглые кнопки `rounded-full`. Типичные отступы страницы/карточки — `p-4` (16 px), строки `p-3.5` (14 px), промежутки `gap-2/3` (8/12 px), между карточками `mb-3` (12 px). Заголовки новых профильных разделов имеют общий `min-h-[74px]`.

Короткие названия товара внутри карточки могут `truncate`; длинный заголовок раздела должен переноситься (`break-words`, `min-w-0`), не вытесняя иконку (`shrink-0`). Не переносить полные названия основных действий на две строки.

Единой экспортируемой клиентской `Button`/`Input` библиотеки нет. Переиспользовать действующую форму/строку, а не создавать фиктивную универсальную обёртку. Основные действия обычно navy/light и gold/dark, `rounded-xl`, flex с иконкой, disabled/ожидание. Success появляется после результата операции, не после одного нажатия. У корзины/оформления собственные размеры основных кнопок; не выравнивать их с маленькими row-actions без задачи.

## Анимации: значения из кода

[Общие значения](../src/lib/motion.ts) и [CSS](../src/index.css): `motionEase=[0.4,0,0.2,1]`, CSS `cubic-bezier(0.4,0,0.2,1)`; `motionExitEase=[0.4,0,1,1]`. Значения TypeScript — секунды.

| Сценарий | Реальная реализация/время |
|---|---|
| Разделы и вкладки | `tabTransition`: направленный сдвиг; `motionTiming.page/section=0.34` (340 ms), общий easing |
| Фото карточка → товар → назад | Native View Transitions; `--loft-photo-duration:340ms`, `--loft-photo-ease:cubic-bezier(0.4,0,0.2,1)` |
| Fallback shared photo | Короткие fade 160/180 ms при невозможности общего фото; не перелёт из неизвестной позиции |
| Профиль / поверхности | `profileTransition`, `SurfaceDialog`, `dialogOrigin`; 340 ms, парные неподвижные слои chrome |
| Галерея | `ProductPhotoViewer`, `viewerOpen/viewerClose=0.34`, общий easing |
| Общий `Collapse` | Height и opacity, `disclosure=0.34` |
| **Реальная панель размера** | В `SizeSelector` свои 250 ms open / 200 ms close, easing `[0.22,1,0.36,1]`; затемнение 200 ms |
| Нажатие обычной кнопки | CSS scale `0.98`, 80 ms на press, 180 ms отпускание |
| Нажатие карточки | CSS scale `0.996`, без изменения layout |
| Индикатор nav | `left/width/opacity`, 250 ms, общий CSS easing |
| Успех/самолёт | `feedback=0.15`, `flight=0.6`, `success=0.26`, `successDelay=0.08`; применять существующий `PlaneFlight` |

`motionTiming.sheetOpen/sheetClose` сейчас равны 0.34, но панель размера их не использует. Это реальное различие, а не повод «исправить цифры» в документационной задаче. Не задавать единую кривую админке: её собственные значения описаны отдельно.

### Правила product transition

1. Перед переходом фиксируются product id, history key, placement, URL фото, прокрутка и положение **после снятия press-scale**.
2. Для открытия source image и `[data-product-hero]` получают общее имя `loft-product-photo`. Движется изображение, а не масштаб всей страницы.
3. При возврате `ScrollRestoration` и `restoreOrigin` восстанавливают источник до конечного снимка; событие `loft:scroll-restored` останавливает поздний повторный scroll.
4. Готовое фото не декодируется повторно; отсутствующий DOM/неподготовленное фото имеют ограниченное ожидание и fallback. В native update callback не ждать animation frame: это может блокировать сам переход.
5. После завершения/прерывания удаляются временные имена, снимки и блокировки. Шапка и нижнее меню остаются неподвижными.
6. Изменение цвета использует [useDecodedImage](../src/lib/useDecodedImage.ts), чтобы не показывать пустой кадр при загрузке.

Не добавлять ещё общий page fade поверх shared image, не менять placement при рендере, не оборачивать fixed/nav в трансформируемого родителя. Для рекомендаций сохранять контекст вложенного товара. Проверять быстрый Back и повторный tap, а не блокировать пользователя таймером.

## Прокрутка, диалоги и уменьшение движения

`useScrollLock` учитывает несколько владельцев. При AnimatePresence блокировка держится до завершения выхода; unmount должен освобождать её. `usePageState` хранит фильтры/выбор по history entry; `ScrollRestoration` — позицию. Не заменять это сбросом `scrollTo(0,0)` в каждой странице.

`useReducedMotion`, проверка media query в маршрутах и CSS `prefers-reduced-motion` сокращают/убирают перемещения; глобальная CSS длительность становится 0.01 ms. Нельзя добавлять независимые анимации без этой ветки. Telegram Back должен закрывать верхнюю поверхность по существующему порядку, затем переходить по истории.

## Адаптивность и доступность

- Основная среда — Telegram Mini App на телефоне; код также обслуживает браузер/desktop Telegram. Поддержка не равна подтверждению всех размеров экрана.
- Списки товаров обычно двухколоночные; формы остаются читаемыми, таблицы имеют горизонтальный scroll внутри, диалоги ограничивают высоту/overflow.
- Нижняя навигация `fixed bottom-0`, `px-4 pb-6 pt-2`, контент оставляет нижний запас (`pb-24/28` по экрану). Шапка sticky. Не закрывать кнопку сохранения нижним меню.
- `index.html` задаёт `width=device-width, initial-scale=1.0`. Единого механизма `env(safe-area-inset-*)` в просмотренных общих компонентах нет. Поэтому не обещать полное покрытие safe areas: проверять реальные iPhone/Telegram viewport, клавиатуру и поворот. В этой задаче padding/viewport не менялись.
- Сохранять native кнопки/поля, доступное имя иконок, `aria-*`, видимый фокус и навигацию клавиатурой. Исторические icon-only кнопки и модалки неоднородны; наличие компонента не является WCAG-сертификатом всей системы.
- Не скрывать логотипы брендов тёмным фоном; использовать существующее оформление изображения. Не менять масштаб страницы ради обхода focus-zoom.

## Чек-лист нового интерфейса

- Найти похожую существующую страницу и переиспользуемую поверхность.
- Сохранить палитру, типографику, отступы, RU/UZ и обе темы.
- Взять иконку из реестра/Lucide, сохранить доступную подпись.
- Предусмотреть loading, проверенное empty, error/retry и cached-data состояния.
- Подключить существующий кеш; после записи обновить связанные данные.
- Сохранить вход/выход, прокрутку, reduced motion, Telegram Back и очистку временного DOM.
- Проверить телефонную ширину, desktop, клавиатуру, длинные названия и нижнее меню.
- Для product transition проверить источник из всех затронутых списков, цвет/размер/галерею и вложенный Back.
- Не менять тексты Telegram-уведомлений при косметической задаче.

Ручную проверку реального iPhone фиксировать отдельно от Playwright WebKit. История последних интерфейсных проверок: [отчёт](product-interface-followup-report.md); она относится к своему этапу, не гарантирует будущие изменения.
