# Варианты товара, админка и менеджерский бот

1. В магазине изменены `ProductPage.tsx`, `SizeSelector.tsx`, `RestockControl.tsx`, `server/notifications.ts` и `api/maintenance.ts`. Удалён клиентский `src/lib/shopSizeGrid.ts`. В админке изменены `AnimatedRoutes.tsx`, `adminNavigation.ts`, `index.css`, `DashboardPage.tsx`, `ChinaPage.tsx`, `CategoriesPage.tsx`, `BrandsPage.tsx` и `AdminAddButton.tsx`. `storeExchangeRate.ts` переиспользует чтение курса для Dashboard и спецзаказов. Старый `dashboardTransition.ts` заменён общей навигацией. Обновлены документация, Graphify и регрессии.

2. Лишние размеры появлялись, потому что карточка объединяла варианты из каталога с полной сеткой подкатегории. Сетка 36–56 теперь используется только в админке. Карточка собирает список из созданных вариантов выбранного цвета.

3. Клиентский RPC возвращает идентификатор, размер, цвет и признак доступности. При продаже последней единицы размер остаётся в списке и показывает подписку на поступление. После пополнения размер снова доступен. Данные вариантов, заказов и подписок в базе не менялись.

4. Общий переход покрывает главную, заказы, спецзаказы, каталог, товары, категории, бренды, таблицы размеров, возвраты, аналитику, рассылки и пять подразделов настроек. История рассылок находится внутри страницы рассылок. Подкатегории редактируются в диалоге. Самостоятельного маршрута безопасности в админке нет.

5. При открытии экран входит справа. При возврате направление обратное. Маршруты используют 340 мс и кривую магазина. Источник задаёт существующая история навигации, при прямом входе действует родительский маршрут. Шапка остаётся на месте, а Suspense показывает существующий skeleton. Прокрутка, фильтры и кеш остаются под управлением действующих компонентов. Диалоги и изменение фильтров не запускают анимацию страницы. При reduced motion экран меняется сразу. Браузеры без View Transition API используют направленный вход.

6. Из репозиториев бот получает только исходящие задания. Обработчиков /start, polling и webhook в проектах нет. Чат менеджеров берётся из серверной переменной либо из RPC с правами service_role. На рабочей базе подтверждено, что anon и authenticated не могут читать эту настройку через RPC, менять закрытую таблицу или получать задания очереди. Endpoint фонового worker проверяет серверный bearer. Ручная отправка в админке требует роли менеджера и обслуживает клиентского бота. Имена переменных менеджерского бота отсутствуют в собранных клиентских JS. [Telegram Bot API](https://core.telegram.org/bots/api)

7. Пути автоматической регистрации и подмены получателя из Mini App не обнаружены. Оба пути отправки теперь используют одну проверку числового ID личного чата или группы. Поля Telegram options отправляются по явному списку. При ошибке конфигурации или доставки задание не отмечается отправленным. Реальные сообщения не отправлялись.

8. USD берётся из прежнего расчёта `confirmedRevenue`. UZS получается умножением этой суммы на текущий `settings.exchange_rate` и округлением до целых сумов. ≈ обозначает эквивалент, пробелы разделяют тысячи. При недействительном курсе строка скрывается. При ручном обновлении и ревизии настроек перечитывается курс. Платежи и возвраты используют прежние записи.

9. Карточки заказов и спецзаказов стоят в двух колонках на широком экране и в одной на узком. После них есть 24 px до самостоятельной скруглённой карточки разделов.

10. Кнопка подкатегории расположена на 12 px ниже скруглённого списка, выровнена по внутреннему краю и использует золотой вариант общей кнопки с плюсом. Идентификатор категории передаётся в существующую форму.

11. Логотипы используют круглый контейнер с нейтральной подложкой, тонкой рамкой, внутренним отступом и object-fit contain. Белые и чёрные изображения читаются в обеих темах. Цвета исходных файлов сохраняются. Буква показывается при отсутствии изображения или ошибке загрузки.

12. Обе production-сборки прошли. Node: 89 тестов магазина и 21 тест админки. Локальный SQL-прогон прошёл. Playwright на desktop Chromium, мобильном Chromium и WebKit: 85 из 87 в общем прогоне, два оставшихся мобильных сценария прошли при отдельном повторе. Lint сохраняет прежние ошибки: 414 в магазине и 258 в админке, новых диагностик по файлу и правилу нет.

13. Ручная проверка остаётся для физического Telegram WebView и внешней конфигурации Bot API. Удалось проверить тип резервного ID из базы, а список участников чата, активный внешний webhook и переменные окружения Vercel в этой сессии не проверялись. Рабочие данные не редактировались.
