# Единое движение магазина — 5 ноября 2026

Финальная проверка: 146 браузерных тестов Chrome (73 сценария на мобильном и настольном экране), 48 проверок WebKit с эмуляцией iPhone, 25 серверных/модульных тестов магазина, 7 тестов админки и production-сборка магазина прошли. Отчёты: `playwright-report/`, `playwright-report-webkit/`. Сохранилось существующее предупреждение Vite о начальном JS-чанке больше 500 kB; отсутствие этого предупреждения или измеренная частота кадров не заявляются.

Категории, подкатегории, бренды, поиск и заголовки подборок главной используют раскрытие от выбранного элемента и обратное закрытие из истории заказов. Связь с источником сохраняется при замене параметров URL в поиске. Прежний переход общей фотографии товара сохранён.

Оформление заказа, этапы оплаты, просмотр чека и выбор размера используют общий `SurfaceDialog`: раскрытие обрезкой от нажатой кнопки, без масштабирования текста и без трансформации предка закреплённых элементов. Макродвижения согласованы на 340 мс, `cubic-bezier(0.4, 0, 0.2, 1)`; быстрый отклик кнопок остаётся отдельным. Основные вкладки пролистываются горизонтально по порядку Главная → Корзина → Спецзаказ → Профиль; обратное направление меняет сторону движения. Для вкладок используется Web Animations: живое содержимое нового экрана и временная неинтерактивная копия видимой области старого. Шапка и навигация не копируются и не перемещаются. Копия не получает фокус, не выполняет действия и удаляется при завершении, прерывании и размонтировании. Горизонтальная область ограничена на html/body/#root, чтобы мобильный браузер не увеличивал ширину экрана во время движения. Переходы товара и разделов сохраняют View Transitions.

В промежуточном кадре WebKit у варианта вкладок со снимками исчезали новые слои, хотя геометрические проверки проходили. Поэтому этот вариант заменён прямым движением; итоговый промежуточный кадр проверен визуально в Chrome и WebKit. Автотесты дополнительно проверяют направление, положение меню, очистку временных слоёв, возврат из поиска после ввода/очистки строки и закреплённую панель оплаты.

Главная подписана только на нужные поля Zustand. Карточки мемоизированы и отслеживают собственное избранное, подборки сортируются при изменении данных; заголовок подборки больше не пересоздаётся при изменении соседней карточки.

Цвета, расположение элементов, тексты Telegram-уведомлений, серверные обработчики и БД не изменены. Админка не изменялась. # Исправление рывков по двум видеозаписям — 4 ноября 2026

Проверены и исправлены переходы из записей магазина: карточки товаров на главной, переключение вкладок, открытие и закрытие спецзаказов из прокрученного списка. Финальная проверка: 126 браузерных тестов в мобильном/настольном Chrome, 38 проверок движения в мобильной конфигурации WebKit, 32 серверных/модульных теста и production-сборка магазина прошли.

## Причины и исправления

- В непустой корзине общий сдвиг родителя создавал новую систему координат для вложенной фиксированной панели «Итого». Панель на несколько кадров отрывалась от нижнего края. Анимация перенесена на содержимое списка; добавлен общий запрет пространственного движения контейнера с фиксированными/липкими потомками.
- Старый и новый снимки всего содержимого имели одно имя, хотя их высота и позиция прокрутки различались. На Back старая страница растягивалась в границы новой. Старый снимок содержимого удалён: в переходе товара отдельно появляется только новое содержимое, в профиле окружающее содержимое остаётся в корневом снимке.
- Именованные карточки оказывались поверх шапки/нижнего меню, меняя их видимость до окончания перехода. Для шапки и меню снимается только конечное состояние: без старого парного снимка и без анимации геометрии, в отдельном верхнем слое. Временные имена снимаются при завершении/прерывании.
- Снимки текста карточки профиля больше не растягиваются вместе с её оболочкой: их размеры зафиксированы по исходным/конечным границам, оболочка раскрывает содержимое обрезкой. Переход фотографии товара и его длительность сохранены.
- Фото спецзаказа раньше появлялось без зарезервированного места и резко сдвигало нижние блоки. Место резервируется; уточнение естественных пропорций происходит плавно после завершения снимка. Пропорции кешируются в памяти для повторного открытия. Конечный размер соответствует естественным пропорциям изображения.
- Позиция прокрутки считывается непосредственно перед заменой страницы. Запоздалое событие scroll больше не сохраняет старую позицию вместо фактической. Повторное применение одного перехода защищено от повторной записи позиции.

## Проверка

Новые сценарии проверяют 22 последовательных кадра панели «Итого» при трёх повторных открытиях, шесть открытий/возвратов из длинного списка, порядок слоёв и отсутствие растянутого старого снимка, загрузку фото с искусственной задержкой и повторное открытие из кеша, а также возврат при ещё не обработанном событии scroll. Промежуточный кадр возврата приложен к отчёту. Обычные сценарии каталога, корзины, оформления, профиля, MFA и админки также проверены.

Повторить WebKit-проверки (браузер устанавливается отдельно):

```sh
npx playwright install webkit
npm run test:e2e -- --config=playwright.webkit.config.ts
```

Отчёты: `playwright-report/` и `playwright-report-webkit/`; артефакты исключены из Git. Мобильный WebKit — настольный тестовый движок с эмуляцией iPhone, не физический iPhone и не Telegram WKWebView. Нативные жесты Telegram и производительность конкретного телефона не измерялись.

Оформление, цвета, тексты Telegram-уведомлений, API и БД не изменены. Админка в этом обновлении не изменялась. Внешняя сеть в браузерных сценариях подменяется: реальные заказы и сообщения не создаются. SQL-наборы повторно не запускались.

- Шапка больше не получает отдельный `view-transition-name`: её положение не анимируется и старый снимок не задерживается после возврата из обуви/каталога/всех товаров.

## Найдено и исправлено

1. Аналитика учитывала неоплаченные активные заказы; главная страница админки суммировала даже отменённые. Оба отчёта теперь используют общую проверку подтверждённого платежа. Старые записи `paid` без `paid_at` не объявляются подтверждёнными автоматически.
2. Подтверждение оплаты отправляло сообщение только по старому `user_chat_id`. Добавлен резервный выбор `user_id` для новых заказов. Текст сообщения сохранён.
3. Селектор размера сохранял старое отображение после смены цвета, хотя форма сбрасывала выбор. Селектор теперь получает актуальное значение формы; ложный вариант `One Size` при отсутствии числовых размеров убран.
4. На узком экране кнопки шапки товаров расширяли страницу и мешали доступу к сохранению. Исправлены перенос и границы окна. Заголовок главной страницы и названия брендов также больше не сжимаются до нулевой ширины.
5. SQL-проверка MFA зависела от наличия факторов у настоящего администратора. Она переведена на временного тестового пользователя внутри откатываемой транзакции.
6. Обновлены React Router до 7.18.2 и `tar` до 7.5.22; lock-файлы обоих приложений обновлены. `npm audit --omit=dev` возвращает 0 известных уязвимостей для обоих проектов. Обновление Router соответствует [исправлению производителя](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6).
