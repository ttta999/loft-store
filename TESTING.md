# Проверка нового движения — 2 ноября 2026

Все 84 браузерных проверки (42 сценария на мобильном и настольном Chrome), 32 серверных/модульных теста и обе production-сборки прошли. Браузерные проверки используют отдельные тестовые данные; настоящие заказы и сообщения не создаются.

## Движение

| Действие | Поведение |
| --- | --- |
| Карточка → товар → назад | Общая фотография меняет положение и размер за 340 мс; отдельные снимки текста не содержат фотографии. Источник запоминается по товару, экземпляру карточки и записи истории. Поддержаны главная, каталог, поиск, бренды и обе страницы избранного |
| Возврат | Позиция прокрутки и фильтры восстанавливаются. Если карточка исчезла, товар открыт напрямую или фото сменилось, используется короткое появление без перелёта |
| Галерея | Фиксированная область с фотографией меняет размер за 280 мс; `object-fit: cover` раскрывает кадр без растяжения. Конечная область соответствует естественным пропорциям изображения. Фон и управление появляются/исчезают согласованно |
| Размеры | Нижняя панель выезжает единым объектом и сохраняется в DOM до окончания закрытия, 260–280 мс |
| Фильтры, адрес, пояснения | Высота и прозрачность меняются за 220 мс, следующий контент перемещается вместе с ними. Стрелка поворачивается. Убраны вложенные кнопки в заголовках фильтров |
| Кнопки | Нажатие до 98%, без пружин. В корзину: проверка наличия → фактическое добавление → галочка и «Добавлено». Повторная проверка защищена от одновременных нажатий |
| Спецзаказ | Самолётик летит вверх после успешного ответа API. Подтверждение не появляется при ошибке; форма сохраняется |
| Вкладки и профиль | Основные вкладки: появление содержимого 200 мс; разделы профиля и детали: сдвиг содержимого на 12–16 px и появление 230 мс. Шапка и навбар остаются живыми, неподвижными элементами. Подложка пункта меню перемещается между кнопками |

## Исправления двух ошибок из записей

- Шапка больше не получает отдельный `view-transition-name`: её положение не анимируется и старый снимок не задерживается после возврата из обуви/каталога/всех товаров.
- Детали заказа и спецзаказа больше не используют снимок всего документа, который перекрывал меню. Их фон остаётся непрозрачным, шапка неподвижна, двигается только внутреннее содержимое. Проверка 20 последовательных кадров контролирует положение и отсутствие трансформации навбара.
- Загруженный модуль страницы теперь доступен синхронно до снимка. Между исходной карточкой и товаром не возникает промежуточного Suspense-экрана.
- Декодирование фото и удержание исходного кадра защищают переход от пустого кадра при автоматическом выборе цвета. Быстрый Back, прокрутка и новый ввод могут прервать переход.
- Тема применяется вне layout основных вкладок, включая прямую ссылку на товар. Telegram Back сначала закрывает галерею или размеры. Прокрутка под галереей блокируется до окончания закрытия.

Учитывается `prefers-reduced-motion`. Использованы существующие Framer Motion и View Transitions, новые библиотеки не добавлялись. API, схема БД и тексты Telegram-уведомлений не изменены.

**Ограничение:** мобильный прогон — эмуляция размеров iPhone в Chrome, не физический iPhone и не нативный Telegram WebView. SQL-проверки ниже выполнены в предыдущем прогоне; новая работа не изменяла SQL. Проверки банка и реальной доставки сообщений не выполнялись.

## Найдено и исправлено

1. Аналитика учитывала неоплаченные активные заказы; главная страница админки суммировала даже отменённые. Оба отчёта теперь используют общую проверку подтверждённого платежа. Старые записи `paid` без `paid_at` не объявляются подтверждёнными автоматически.
2. Подтверждение оплаты отправляло сообщение только по старому `user_chat_id`. Добавлен резервный выбор `user_id` для новых заказов. Текст сообщения сохранён.
3. Селектор размера сохранял старое отображение после смены цвета, хотя форма сбрасывала выбор. Селектор теперь получает актуальное значение формы; ложный вариант `One Size` при отсутствии числовых размеров убран.
4. На узком экране кнопки шапки товаров расширяли страницу и мешали доступу к сохранению. Исправлены перенос и границы окна. Заголовок главной страницы и названия брендов также больше не сжимаются до нулевой ширины.
5. SQL-проверка MFA зависела от наличия факторов у настоящего администратора. Она переведена на временного тестового пользователя внутри откатываемой транзакции.
6. Обновлены React Router до 7.18.2 и `tar` до 7.5.22; lock-файлы обоих приложений обновлены. `npm audit --omit=dev` возвращает 0 известных уязвимостей для обоих проектов. Обновление Router соответствует [исправлению производителя](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6).

## Повторный запуск

Требуются Node.js 24, установленный Google Chrome и локальные копии обоих репозиториев с установленными зависимостями.

Из каталога магазина:

```sh
npm ci
npm ci --prefix /path/to/loft-store-admin
LOFT_ADMIN_ROOT=/path/to/loft-store-admin npm run test:all
```

Можно сохранить только путь `LOFT_ADMIN_ROOT` в локальном `.env.e2e.local` (игнорируется Git). Тогда достаточно `npm run test:all`.

Отдельные команды:

```sh
npm test
npm test --prefix /path/to/loft-store-admin
npm run test:e2e
```

HTML-отчёт последнего браузерного прогона: `playwright-report/index.html`. При ошибке сохраняются снимок экрана и trace в `test-results/`. Эти артефакты не публикуются в репозитории.

SQL-наборы: `db/03`, `05`, `06`, `11`, `12`, `13`, `15`, `16`. Запускать весь файл с `BEGIN` и заключительным `ROLLBACK`, не отдельные фрагменты. Миграции при этом не применяются.

## Границы проверки

- Браузерные тесты используют настоящие компоненты приложений, но перехватывают ответы Supabase, Telegram и клиентского API. Отдельные тесты запускают настоящие обработчики API, также с подменой внешней сети.
- PostgreSQL-наборы выполнялись на настоящих функциях проекта в транзакциях с откатом. Строки тестовых заказов, товаров и пользователей не сохраняются. Последовательности номеров PostgreSQL могут получить пропуски: их значения не откатываются.
- Настоящие сообщения клиентам не отправлялись; реальные заказы и учётные записи не изменялись. Проверка банка, реальной доставки Telegram и нативного Telegram WebView требует отдельной проверки на тестовых получателях/устройстве.
- Нагрузочное тестирование, все возможные комбинации данных и полный аудит исходников сторонних библиотек не выполнялись.
- Полный npm audit всё ещё сообщает 34 предупреждения в инструментах разработки/сборки (18 moderate, 16 high). Критическое предупреждение `tar` устранено. Несовместимые обновления/понижение `@vercel/node` автоматически не применялись; рабочие зависимости по `--omit=dev` чисты.
