# Защита магазина и порядок обновления

Новый браузерный клиент читает только каталог и настройки витрины. Заказы, заявки, подписки и загрузки проходят через `/api/store`; сервер проверяет короткоживущую подпись входа Telegram и подписанную сессию, определяет владельца, ограничивает частоту запросов и вызывает закрытые функции базы. Сессия хранится только в памяти вкладки. Цена, доставка, скидки, курс и остатки определяются базой. Чек не подтверждает получение денег автоматически.

## Переменные Vercel

В проекте магазина нужны `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_MANAGER_BOT_TOKEN`. При необходимости `SUPABASE_URL` заменяет серверное использование `VITE_SUPABASE_URL`. `TELEGRAM_MANAGER_CHAT_ID` по умолчанию сохраняет существующего получателя магазина.

В админке нужны URL/anon key и серверные `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN`. Серверный ключ и токены ботов никогда не должны иметь префикс `VITE_`, находиться в Git или передаваться покупателю.

## Согласованный выпуск

1. Установить `db/01_store_backend.sql` и `db/04_admin_operations.sql`. Эти добавления уже применены в проекте `kmbmsbydxnxxiwypaxwm`; старый клиент продолжает работать. Перенос связи спецзаказа с UUID на text исправляет несовместимость с bigint ID заказов.
2. Развернуть новые версии **магазина и админки**. В админке должны быть изменения приватных ссылок, авторизованной отправки сообщений, проверки менеджера и атомарной отмены/подтверждения оплаты.
3. Проверить `/api/store`, `/api/validateTelegram` и `/api/sendNotification`, вход через Telegram, историю, новую заявку, оформление, чек и отмену. Неподписанные запросы магазина должны получать 401; прежний публичный отправитель магазина — 410; отправитель админки — 401.
4. Применить `db/02_lockdown.sql`. После этого анонимному пользователю недоступны заказы, подписчики, заявки, изменение каталога/настроек и загрузка файлов. Чеки и фото заявок становятся приватными. Каталог остаётся публичным. Старые публичные ссылки преобразуются при чтении в временные ссылки.
5. Запустить проверки прав и Supabase advisors. Не откатывать клиент на старую версию при закрытых правилах базы: сначала исправить серверную версию. Не возвращать открытые права ради восстановления старого клиента.

Текущий единственный пользователь Supabase Auth сохранён в явном списке менеджеров `private.store_admins`. Новые аккаунты не получают права автоматически. Список изменяется только администратором базы. Не используйте `user_metadata` для прав доступа.

## Проверки

- `npm test`: подпись и срок Telegram, защита сессии, идентификаторы, форматы/размер файлов, запрет запросов без входа, ограничение истории владельцем и удаление подставленных полей оплаты/цены/склада.
- `npm run build`: TypeScript клиента **и сервера**, сборка Vite.
- `db/03_verify_backend.sql`: реальные проверки транзакций с тестовыми записями и `ROLLBACK`; не отправляет сообщения в Telegram. Проверяет расчёт цен, скидок, доставки, повторные запросы, чужую отмену, возврат остатков, спецзаказы и защиту чека при автоматической отмене.

## Ограничения и обслуживание

Уведомления создаются только по сохранённым событиям, с фиксированным серверным получателем и текстом без HTML. Outbox исключает обычное повторное отправление при повторе запроса. После сетевого сбоя запись остаётся для повторной попытки; автоматического фонового обработчика пока нет. Не гарантируется ровно одно сообщение при неоднозначном сетевом сбое Telegram. Не отправляйте заказы повторно ради уведомления.

Загрузка допускает JPG/PNG/WebP до 2 МБ с проверкой заголовка файла на сервере, без доверия имени или указанному браузером MIME. Ограничения хранилища и частоты запросов обязательны. Антивирусная проверка/полное перекодирование изображений не реализованы.

Отмена сохраняет запись заказа как «Отменён» для защиты от повторного списания/возврата остатков. Отмена оплаченного заказа менеджером помечает возврат как `refund_pending`; деньги автоматически не переводятся. Старые записи с оплатой при получении, которые прежний клиент уже отметил `paid`, автоматически не исправляются: нужна сверка с реальными платежами.

Ссылки на приватные изображения действуют 15 минут; для обновления нужно заново загрузить историю. В админке необходимо обновить страницу, если ссылка устарела.

Проверки Supabase могут отмечать намеренные `SECURITY DEFINER` функции: проверку списка менеджеров, защищённые операции менеджера и публичную агрегированную популярность товаров. Это ограниченные интерфейсы; они не должны раскрывать исходные заказы. Таблицы `private` закрыты RLS без клиентских политик намеренно. [Описание проверки привилегированных функций](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable).

В Supabase Auth отдельно обнаружена выключенная защита от скомпрометированных паролей. В доступном коннекторе нет изменения этой настройки; её нужно включить в настройках Auth, если тариф поддерживает. [Документация Supabase](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
